# New API 渠道月度消费限制

一个 New API 请求处理插件。它按上海时间的自然月统计站内消费，在预算用尽后拦截符合规则的后续请求。每月 1 日 00:00 自动开始统计新月份。

## 安装与配置

1. 用 Root 登录 New API，在 **插件管理 → 上传插件** 导入 [`newapi-channel-monthly-budget.js`](newapi-channel-monthly-budget.js) 并启用。
2. 创建 `nap_` 个人访问令牌，只授予 `log:read` 权限。令牌所属账号须具备读取全站日志统计的管理员权限。
3. 进入 **请求处理 → 添加**，选择 **渠道月度消费限制**。填写 New API 管理地址、访问令牌、月度额度和每美元配额点数。管理地址填本实例的域名与端口。配额点数以本实例 `/api/status` 返回的 `quota_per_unit` 为准，插件默认填 `500000`。
4. 根据需要选择规则范围。保存后，可用 **试一试** 选择协议和渠道 ID，检查插件能否读取用量并按阈值判断。

## 预算模式

| 需求 | 配置 |
| --- | --- |
| 每条渠道各有相同的月度额度 | 选「每条渠道独立额度」，范围选「所有请求」。例如填 `100`，每条渠道各有 $100。 |
| 每条渠道可以设不同金额 | 每条渠道创建一个实例，选「每条渠道独立额度」和「只在渠道添加」。在 **编辑渠道 → 请求与响应 → 请求处理插件** 绑定各自实例。例如 A 填 `100`，B 填 `200`。 |
| 所有渠道共用一个月度额度 | 选「所有渠道共用总额度」，范围选「所有请求」。例如填 `100`，全站共享 $100。 |

为渠道单独设额度时，请检查已有的全局实例。适用的实例都会运行，较低的全局额度也会拦截该渠道的请求。

## 统计与拦截

- New API 实例需要开启「记录额度消耗」，并保留本月的消费日志。插件在预算检查时读取 `/api/log/stat`，按站内消费合计判断。退款单独记录，消费合计不会扣除退款。
- 达到额度时，New API 返回 HTTP 400，提示中包含 `monthly_budget_reached`。本次请求结束，渠道保持启用，次月会按新的月份继续判断。已经发往上游的请求仍可能让金额超过额度。
- 逐渠道模式依赖选中渠道后的请求处理阶段。音频和部分 Realtime 入口可能跳过该阶段。
- 已在 New API `v1.0.0-rc.51` 的插件运行时通过模拟统计接口验证 OpenAI、Claude 和 Gemini 请求、两种预算模式、跨月和异常响应。
